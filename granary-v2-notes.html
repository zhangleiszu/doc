1. 论文解读：标题、摘要与双身份

标题与摘要（中英对照要点）

标题：Granary-v2: Scalable Multilingual Speech Data Curation for Predictable and Controllable Model Outputs (Technical Report)
译文：Granary-v2：面向可预测与可控模型输出的可扩展多语言语音数据治理（技术报告）

摘要要点内容
数据规模全量 843,579 小时独立音频、48 语言、19 语料条目、2.134 亿条语句；高质量标记 317,724 小时
翻译覆盖约 142,778 小时译入英语；约 55,772 小时英语译出至 31 种目标语言
系统构成基于 NeMo Curator：语言相关 ASR 标注 + 转写改善 + 文本标签生成
对齐目标忠实语音转写、带/不带非流利的书面形式、语码转换转写、字幕、问答对、翻译
过滤实验同训练步数预算下，过滤使九基准未加权平均 WER 从 4.91% → 4.67%（六基准提升）
开源流水线（NeMo Curator tutorials）+ 训练配方开源；HF 公开子集（16 条目 / 463,062 小时）

双身份：流水线 + 数据集

Granary-v2 既指可复用的数据治理系统（三条子流水线），也指该系统产出的数据集（带标签的 84 万小时音频）。论文中 "uses Granary-v2 as part of its training data" 指数据集那一面。

Nemotron-3.5-Transcribe 的角色（答疑）

不是纯 ASR 模型，而是语音-语言模型：约 6 亿参数的 TDT 编码器（从 Granary-v2 预训练检查点初始化，每 80ms 一个表示）+ 投影层 + 语言模型解码器 + 强化学习。一个模型同时做 ASR 与语音翻译，用 prompt 控制输出。论文表 12：FLEURS ASR 37 语言 WER/CER 均值 9.29%；FLEURS 翻译 X→英 BLEU 29.20 / 英→X 26.54。

2. 三条流水线与数据集输出格式

三条流水线（论文第 3 节）

流水线组成产出
① 元数据提取16kHz 重采样 → 说话人分离（RTTM）→ VAD 切 0.5–40s 段 → 声音事件 → 语言识别Opus 片段 + JSONL manifest（说话人数/事件/语言码）
② ASR 标注语言路由选"主模型 + 恢复模型"对（表 3，48 语言 A–H 组）；或人工转写改进模式忠实语音转写（口语数字形式、保留非流利）
③ 文本标签生成实体恢复→标点→语言验证→TN→[字幕/语码转换/问答]→ITN→去非流利；质量过滤；上下文标签；翻译；指令打包对齐的多种文本目标 + 指令-目标对

发布记录 Schema（附录 E 表 18）

{
  "audio_filepath": "…",            // 记录标识符（音频另从原分发方获取）
  "duration": 8.11, "corpus": "…", "source_lang": "…",
  "tn_raw": "…",                    // 口语形式转写（共同源）
  "itn_raw": "…",                   // 书面形式（保留非流利）
  "itn_clean": "…",                 // 书面形式（无非流利）
  "captioning_text": "…", "code_switched_text": "…", "speech_qa_text": "Q…A… 或 SKIP",
  "context_asr": { "coarse": …, "fine_terms": […], "distractors": […], "prompts": [5 变体] },
  "translations": { "eng": { "translation_raw": …, "translation_quality_score": … } },
  "preference_instructions": [ { "prompt": …, "target": …, "tags": {"type":…, "target_lang":…} } ],
  "high_quality": true
}
同一音频的多种转写/翻译只是标签，不增加音频小时数；行粒度 = VAD 语音段，全链路从不聚合回父录音（溯源靠 original_file/start_ms/end_ms）。

4. metadata 流水线：数据格式

输入（每条录音一行）

{"audio_filepath": "/data/recording.wav", "audio_item_id": "recording_001"}

输出目录与 JSONL 字段

output/ ├── metadata.jsonl  # 每语音段一行 + 无语音审计行
        ├── audio/          # Opus 片段   ├── rttm/   # 说话人轮次
        ├── resampled/      # 16kHz WAV   └── speechbrain_cache/
字段含义
audio_filepathOpus 片段绝对路径；vad_empty 审计行保留原录音路径
original_file / audio_item_id父录音 / 段级稳定 ID
start_ms / end_ms / duration / sample_rate段偏移（毫秒）、段长、16000 Hz
num_speakers / rttm_filepath重叠说话人数 / 录音级 RTTM 相对路径
sed_events声音事件（相对本段起止秒 + superclass）
source_lang选定语言码；缺失为空串；模型不一致为 skipped
additional_notes / _skipme / vad_empty模型置信度与拒绝原因 / 行级标记 / 无语音审计

5. indic_asr：11 个 Stage 逐段精读

阅读约定：贯穿示例 = yt1001_seg000000（8.11s 印地语 VAD 段，生产串联场景：metadata 输出直连 ASR 管线）。缩写：R=reference_text、P=primary_model_prediction（Canary）、F=fallback_model_prediction（Parakeet）。每个 Stage 给出完整输入行与完整输出行（所有字段全列出、无省略，红色=该阶段新增或变化的字段，灰字为行内注释）；关键变体路径也以完整行快照展示。波形以 <float32 [1, 129760]> 表示内存张量（不落盘）。

S1 读 → S2 校验+波形 → S3 Canary(P) → S4 查P → S5 Parakeet(F) → S6 查F(可救) → S7 选择 → S8 正则清洗 → S9 缩写拼接 → S10 WER → S11 落盘

6. indic_asr 关键概念问答

Q：`_skipme` 是什么？"被标"是什么意思？

行级状态标记位（"skip me"）。空 = 干净；非空 = 该 VAD 段质量未决——软性未通过，不删除：行保留落盘、绕过 Stage 8/9 清洗、生产口径排除出需有效转写的阶段。可被救回（路径 B/C 清标记）。

取值写入者含义
""Stage 2 / 救回分支干净
Hallucination:WhisperHallucination_primary/_asrStage 4 / 6幻觉家族标记（值结构 = 类型:写入者实例名）
lang_not_supported:{stage} / not_supported / audio_load_error / Empty after regex cleaningStage 3/5/7/ASR 基类/Stage 8其它家族

additional_notes = 历史账本（只增不删），_skipme = 当前状态（单一真相源）。

Q：选择规则（哪个模型上位）？

默认选 Canary(P)，仅"对 P 有实证不利"才换人：P 被标 + F 干净（recovered 信号）→ 选 F；双标 + 一致度高（WER≤20%）→ 误报平反保 P；双标 + 不一致 → 形式上写 P 但标记保留（行出局待审计，教程基准 21.6 万行中 37 条）。

Q：唯一词比是什么？

len(set(words))/len(words) ≤ 0.4 即标——正常语言接近 1，解码器循环复读骤降；≥60% 重复才标记，给口语合理重复留余量（歌词/口号会误标，故设计为软标记）。

Q：WER/CER 怎么算？

标准 Levenshtein（替换/插入/删除各计 1）：WER 按空白分词、CER 按 Unicode 字符；除以参考词数 ×100。Stage 7 的一致性计算先去标点小写；Stage 10 的评估计算裸比较。

Q：JSONL 输出的目的与粒度？

跨流水线数据契约（metadata→ASR→text_pipeline 靠 manifest 串联）+ 审计账本 + 断点恢复载体 + HF 发布实体（label manifest）。行粒度 = VAD 语音段，永不聚合回父录音。

8. text_pipeline 关键概念问答

Q：TN 与 ITN 的区别？

TN（Stage 5）ITN（Stage 7）
方向书面→口语（3→three、$12.50→twelve dollars and fifty cents）口语→书面（反向）
非流利保留保留（itn_clean 才删）
守卫none（膨胀合法）itn（增加/新词可疑）
产物角色tn_raw 共同源、逐字转写训练目标itn_raw 书面目标、itn_clean 底稿

串联一对可逆变换，非流利原样穿过两者；tn_raw（怎么说）与 itn_raw（怎么写）构成同一段语音的对齐双目标，删除被隔离在 S8。

Q：fallback 注记需要自己编码吗？

不需要——检测（_check_novel_words：拉丁字母段提取 + 白名单 + 罗马数字）、判决（_validate）、回退+写注记（_read_response + 提交阶段）全部内置于 AudioTextLLMStage 基类；YAML 只开关（validation_mode）和调阈值。仅扩白名单/新增守卫类型才需子类化写代码。

Q：Primary / Languages 是谁的预测？

都是 Stage 4 的 LLM 读 pnc_text 的预测：Primary=文本主导语言，Languages=全部在场语言；metadata 的声学预测在 source_lang 字段（verify 的 expected）。primary≠expected 但 expected 在列表 → 多语言分支放行（语码转换优先信任，分歧留注记 source present/absent）。
